# Модель производительности и применение настроек

## Назначение технологий: проверенные источники

Прочитаны официальные страницы [NVIDIA DLSS](https://www.nvidia.com/en-us/geforce/technologies/dlss/), [AMD FSR 3](https://gpuopen.com/fidelityfx-super-resolution-3/), [NVIDIA HairWorks](https://developer.nvidia.com/hairworks) и [NVIDIA RTX](https://developer.nvidia.com/rtx/ray-tracing). На момент проверки все четыре ответили HTTP 200.

Super Resolution реконструирует изображение, позволяя уменьшить стоимость внутреннего рендера. Frame Generation добавляет промежуточные кадры; это не такое же увеличение частоты расчёта правил или отклика ввода. Дополнительные геометрия, освещение, трассировка и эффекты могут увеличивать стоимость кадра. Фиксированных универсальных процентов потерь или ускорения нет: они зависят от сцены, реализации и устройства. PhysX может иметь разный профиль нагрузки на CPU/GPU, поэтому фиксированные 10% здесь — дизайнерское значение, не измерение SDK.

## Правило модели

X — измеренная частота фактических отрисовок без искусственного ограничения. Это доступная производительность данной сцены в браузере, а не достоверно определённая частота монитора. X может совпадать с 165 Гц на одном устройстве и быть существенно ниже на другом.

`target = X × costs × upscaler × generation`.

| Параметр | Множитель |
| --- | --- |
| NVIDIA HairWorks | 0,7 |
| Ray Tracing | 0,2 |
| Path Tracing | 0,3 |
| NVIDIA PhysX | 0,9 |
| HBAO+ | 0,9 |
| FXAA / TAA / MSAA 8× / DLAA | 0,97 / 0,95 / 0,8 / 0,9 |
| Multi Frame Generation | выкл.: 1; ×2: 2; ×3: 3; ×4: 4 |
| DLSS Quality / Balanced / Performance / Ultra | 1,3 / 1,5 / 1,8 / 2 |
| FSR Quality / Balanced / Performance / Ultra | 1,25 / 1,45 / 1,7 / 1,9 |
| XeSS Quality / Balanced / Performance / Ultra | 1,2 / 1,4 / 1,6 / 1,8 |

Выключенные эффекты дают 1. Значения перемножаются. Например, 0,2 × 0,3 = 0,06: при X=165 оба режима дают 9,9 FPS. RT с генерацией ×4 даёт 132 FPS, а дополнительное усиление может вернуть доступную базу. Выше X имитация не ускоряет реальный рендер и не подделывает счётчик.

В реальных играх Path Tracing часто является полным режимом трассировки, а не независимой надстройкой. В этой пробе оба множителя намеренно комбинируются по прямому указанию пользователя. Названия технологий описывают терминологию; настоящих SDK, реального апскейлинга и синтеза промежуточных изображений здесь по-прежнему нет. Увеличивается частота фактических отрисовок, ранее ограниченная моделью. Будущая физика/логика не получает дополнительные шаги при выборе генерации.

Минимум от эффектов — 1 FPS, чтобы экстремальное сочетание не оставляло сцену без изображения надолго. Если сама база ниже 1 FPS, минимум не повышает её. Ручной лимит и будущий cinematicCap ограничивают результат сверху, усиления их не обходят. При итоговом множителе ≥1 искусственный лимит снимается; естественную границу задаёт устройство/браузер. FPS не округляется до целого при планировании кадров.

## Измерение и пределы достоверности

Для базы используются только реальные отрисовки активной видимой сцены. Нужно ≥1,5 секунды и ≥3 интервала; на медленном устройстве это занимает дольше. На время начального замера ограничения не действуют. Затем X фиксируется, а не пересчитывается из уже ограниченных кадров. Пауза/скрытие прерывают незаконченный замер. Настройка реального качества после применения запускает новый замер.

Это короткая оценка конкретной сцены, не полноценный бенчмарк и не определение модели GPU/монитора. Новая нагрузка ОС, смена окна и оборудования могут изменить реально доступную частоту после замера; счётчик покажет фактический результат, который может быть ниже расчётного. Перезагрузка или изменение реального качества повторяют измерение.

## Форма и действующее состояние

Все параметры «Видео», в том числе качество сцены и ручной лимит, сначала попадают в форму. Справа под описанием — «Применить настройки». Изменения не действуют до её нажатия. Действующий предел и предпросмотр после применения показаны раздельно.

F8 и «Сбросить настройки» сбрасывают форму, но не обходят применение. Переключение вкладки и закрытие сохраняют неприменённую форму в этой сессии. Перезагрузка сбрасывает всё. «Звук» и громкость применяются сразу. Окно не меняет положение/размер при переходах между вкладками; Esc, крестик и фон закрывают его, фокус возвращается к кнопке открытия.
