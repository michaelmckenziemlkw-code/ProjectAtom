## Что уже было готово ДО этой задачи

Babylon.js + TypeScript + Vite, программный жук, окружение, три визуально разных жеста (wave/tap/scrape) и знаки. Контракт BeetleActor: root, present, dispose; асинхронная фабрика поддерживает будущую замену модели, но реального GLB-загрузчика ещё нет.

В 8658664 проверены сборка, 13 модульных и 7 браузерных тестов. Это история базовой версии; после новых изменений требуется новый прогон. Команды:

```sh
npm ci --cache /tmp/projectatom-npm
npm run test:unit
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm test
npm run dev
```

Node >=22.18, рекомендуется 24 LTS. Для Windows: npm.cmd ci / npm.cmd run dev. Браузерные тесты работают с производственной сборкой через Vite preview на 4173, программный WebGL может быть медленным. В базовой версии timeout 120 секунд, один worker. Текущая машина уже содержит зависимости и Chromium. Проверять фактическое наличие в новой среде.

Настройки оформлены серьёзно: графит, красное выделение, голубые значения, локальный Roboto Condensed с кириллицей. Нет надписей про пародию/понарошку. «Звук» — выключатель и громкость 0–100% через общий GainNode. «Видео» — отдельные черновые и применённые параметры, справа кнопка «Применить настройки». Изменение формы, F8, сброс, закрытие и смена вкладки не применяют видео. Громкость меняется сразу. Настройки действуют только до перезагрузки.

Модель FPS: базовая частота X измеряется по реальным неограниченным отрисовкам за >=1,5 с и >=3 интервалов, затем фиксируется. HairWorks ×0,7; RT ×0,2; PT ×0,3; PhysX и AO ×0,9; генерация ×2/×3/×4; DLSS/FSR/XeSS усиливают результат по режиму. Не подделывать счётчик и не обещать ускорение выше доступного устройства. Подробности и официальные источники — docs/design/FPS.md. При реальной смене качества сцены повторяется замер. Звук и ход времени независимы от допуска к отрисовке.

Общий запас подсказок 10; одно событие beetle с 3 платными последовательными уровнями. Чтение открытого уровня и смена варианта бесплатны, максимум расхода 3. Не возвращать бесплатный ответ в настройки и не выводить признаки/решение автоматически. Прежний обычный HUD не должен подсказывать, что рассматривать у жука.

## Последние требования пользователя — основной объём текущей задачи

### Меню по Escape

- В игре Escape открывает небольшую вертикальную центральную панель: «Продолжить игру», «Настройки», «Выйти из игры».
- По типу My Summer Car это меню БЕЗ остановки игрового времени. Сцена и таймер продолжаются в меню и настройках. Движение червя от ввода прекращается, пока игрок управляет меню.
- Повторный Escape или «Продолжить» возвращает управление персонажем.
- «Настройки» открывают существующее большое окно «Звук / Видео». Обратный переход возвращает к маленькому меню. Сохранить отложенное применение, громкость и внешний стиль.
- «Выйти» в браузерной технодемке может возвращать на стартовый экран с завершением текущей попытки; не пытаться закрывать произвольную вкладку через window.close. Полноценное главное меню пользователь предложил проектировать ПОСЛЕ проверки этой демки.
- Удалить экранные кнопки «Пауза», «Приблизиться», «Общий план», кнопку настроек в правом верхнем углу. На игровом экране нет кнопок, для которых нужен курсор.
- Нынешняя ActiveClock останавливается на скрытии вкладки и прежней паузе. Для игрового режима это необходимо изменить: часы запущенной попытки не должны останавливаться из-за меню. Не утверждать, что два клиента уже синхронизируются: общий пакет старта и роли ещё не перенесены в 3D.

### Червь и камера

- Добавить собственную программную объёмную модель червя и играть за него от третьего лица.
- WASD — движение, направление относительно камеры. Обзор мышью без удержания кнопки, как в GTA. Предпочтительно Pointer Lock с явным пользовательским жестом; Escape отпускает мышь для меню, продолжение возвращает её в игру.
- Управление не должно залипать при открытии меню, потере фокуса, скрытии и выходе. При недоступности Pointer Lock показать корректное сообщение/повторный запрос, а не молча возвращать старый drag-обзор.
- Червь должен быть виден, двигаться около жука и не проходить через него/стенки прохода. Камера следует за червём и обходит/приближается у препятствий, насколько требуется для этого небольшого фрагмента.
- Сохранить видимые знак и жест жука. Жук — препятствие, не второй игровой персонаж.

### Подстилка и уход жука

- Дать локальное действие положить подстилку сбоку около жука и показать последовательную анимацию: жук подходит, подбирает её и уходит, проход открывается.
- Предлагаемый для реализации ввод: E около жука. Это техническое действие для проверки сцены, не готовая голосовая загадка/операторский интерфейс. Пользователь прямо допускает условный сценарий технодемки.
- Не добавлять автоматически всю эстафету, здоровье, еду, грибы, бомбу, сетевой сервер, роли или полноценные синематики. Эти части остаются следующим проектированием после проверки управления.
- Модели программные, Blender не является обязательным условием. Никаких неподтверждённых утверждений о проверенном импорте GLB.

## Технический план (пока не означает реализацию)

- core: небольшое независимое состояние прогулки, положение/направление червя, ограничения прохода, столкновение с жуком; движение маленькими фиксированными шагами независимо от лимита render. Отдельная временная шкала ухода жука по монотонному времени.
- render/models: процедурный червь; добавить походку существующему жуку, сохранив его жесты в ожидающем состоянии.
- render/createStudyScene: следящая камера с углами мыши, представление состояния мира, подстилка и смена положения жука.
- ui: маленькое Escape-меню и сохранённые настройки, Pointer Lock и клавиатура. Подсказки/варианты технической проверки перенести в меню, убрать интерактивные кнопки из игрового HUD. Допустимы пассивные FPS, подсказка клавиш и контекст действия E без выдачи знака/жеста/решения.
- main: запуск/завершение попытки, время без паузы из-за меню, ввод, правила и рендер раздельно. Потеря фокуса очищает ввод; глобальное время не откатывается и не замедляется.
- Проверки: чистые правила движения и коллизий, одинаковая скорость при разном FPS, уход по времени; браузерный Pointer Lock, мышь/WASD, Escape/продолжение/настройки/выход, время при открытом меню, подстилка и открытие прохода, старые видео/звук/подсказки, узкий экран, WebGL/context loss.
